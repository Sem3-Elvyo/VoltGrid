# Team workflow (GitHub is graded)

The circular says evaluators check **version history and per-person contributions**, and that the repo must be updated regularly.

1. `main` is always deployable. Nobody commits to it directly after week 1.
2. One branch per feature: `feature/<name>-<thing>`, e.g. `feature/riya-booking-form`.
3. Small commits, imperative messages: `Add plate validation to BookingForm`.
4. Open a pull request; **a different teammate reviews** it before merge.
5. Commit from your **own** GitHub account, at least weekly, so history shows everyone's work.
